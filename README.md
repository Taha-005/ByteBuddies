# Byte Buddies — Smart Business Agent

A chat agent for **Byte Buddies**, a fictional weekend coding & robotics school for kids aged 8–14 in Hamra, Beirut. The agent ("Bitsy") answers parents' questions, collects leads, and records feedback and unanswered questions. It runs on the **Gemini API** and has a **Gradio** chat UI.

## The business

Byte Buddies runs three weekend programs: **Byte Starters** (8–10, Scratch + LEGO SPIKE), **Byte Builders** (11–12, Python + micro:bit), and **Byte Makers** (13–14, Python projects, Pygame, competition robotics). Classes are 2 hours on Saturdays/Sundays, in 10-class terms ($180 / $200 / $220 per term, plus a $20 registration fee), with a free trial class for new students.

- `me/business_summary.txt`: short overview
- `me/about_business.pdf`: full profile (story, curriculum, team, pricing, FAQ), generated by `make_pdf.py`

Some topics are **deliberately left out** (online classes, refund policy, sibling discounts) so the agent's "I don't know → record it" behavior can be demonstrated.

## How the agent works

Everything is in `business_agent.ipynb`:

1. **Persona** (`PERSONA`): who Bitsy is (name, role, audience, tone, style).
2. **Instructions** (`INSTRUCTIONS`): the rules. Answer only from the business content, never invent facts, record unknown questions, collect name + email for leads, encourage interested parents to leave their contact info, stay in character, and a **parent-only guardrail** (no contact details are collected from children).
3. **Router** (`route_message`): a lightweight Flash-Lite call that classifies every message as `general_question`, `lead_collection`, or `feedback`, using recent history for context. Invalid output falls back to `general_question`.
4. **System prompt** (`build_system_prompt(route)`): PERSONA + INSTRUCTIONS + summary + PDF text + a route-specific instruction.
5. **Tools** (function calling):
   - `record_customer_interest(email, name, message)` appends the lead to `leads.log`
   - `record_feedback(question)` appends the unanswered question or feedback to `feedback.log`

   Both print what they recorded and return `{"status": "recorded"}`.
6. **Chat loop** (`chat`): route → build prompt → call the Flash model with the tools → run any requested tools and send back their results → repeat until the model replies with text.
7. **Gradio UI** (`gr.ChatInterface`): under every reply it shows the detected **route** and any **tool called**. These lines are stripped from the history before it is sent back to the model.

| Setting | Value |
|---|---|
| API | Gemini, via its OpenAI-compatible endpoint (`openai` Python SDK) |
| Chat model | `gemini-3.8-flash` |
| Router model | `gemini-3.5-flash-lite` |

## Setup (Windows / PowerShell)

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Then create a file named `.env` next to the notebook containing your key from Google AI Studio:

```
GEMINI_API_KEY=your-key-here
```

`.env` is git-ignored and never committed.

## How to run

1. Open `business_agent.ipynb` (VS Code or Jupyter) and select the `.venv` kernel.
2. **Run All.** The last cell launches the Gradio chat and opens it in your browser at http://127.0.0.1:7860. It may also appear inline in the notebook, but VS Code can show that inline view as a blank box.
3. Optional: regenerate the PDF with `python make_pdf.py`.

### On Google Colab

1. In Colab: **File → Upload notebook** → `business_agent.ipynb`.
2. Click the **key icon (Secrets)** in the left sidebar → add `GEMINI_API_KEY` with your key, and turn on *Notebook access*.
3. **Runtime → Run all.** The first cell installs the libraries and shows an upload button; select both `business_summary.txt` and `about_business.pdf`.
4. The chat appears under the last cell. Logs are in the **Files** panel and are deleted when the Colab runtime ends.

If a model ID stops working, check the model list in Google AI Studio and update `CHAT_MODEL` / `ROUTER_MODEL` in the first code cell. A 429 / `RESOURCE_EXHAUSTED` error means the free-tier rate limit was hit; wait a minute and try again.

## Where the logs go

Both files are written next to the notebook and are git-ignored:

- `leads.log`: `[timestamp] name=... | email=... | notes=...`
- `feedback.log`: `[timestamp] question=...`
